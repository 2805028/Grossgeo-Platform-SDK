# Лицензионное соглашение продукта в User Panel

> Для разработчиков продуктов GrossGeo. Как сделать так, чтобы участник принимал ваше лицензионное соглашение в
> User Panel до установки или покупки продукта, и как плагин узнаёт об этом через SDK.
>
> См. также: [Publishing API](grossgeo-publishing-api-guide.md) — выпуск релизов из своей утилиты;
> [SDK 2.4 — соглашения и согласие](grossgeo-sdk-2.4-guide.md#соглашения-и-согласие) — сторона плагина.

---

## 1. Как это работает

1. К выпуску прикладывается **редакция соглашения**: код, название, текст в Markdown и признак «продукт отправляет
   счётчики команд». Редакция создаётся один раз и не меняется; другой текст — новая редакция.
2. Перед установкой, обновлением, покупкой, пробным периодом, сменой тарифа, покупкой сопровождения и докупкой мест
   User Panel показывает окно «Лицензионное соглашение «{продукт}» — {студия}». Под текстом — галочка счётчиков (если
   продукт их отправляет) и кнопки «Отказаться» / «Принимаю». Enter и Esc означают «Отказаться»: принять можно только
   щелчком.
3. **«Принимаю»** — принятие записывается в учётную запись участника под кодом соглашения и отпечатком текста, после
   этого начинается установка или оплата. **«Отказаться»** — ничего не скачивается и не покупается, решение не
   записывается; уже установленная версия продукта работает дальше.
4. Плагин спрашивает `GetState(код, отпечаток)` и получает `Accepted` с `Source = Account` — своё окно не показывает.

Редакцию с тем же кодом и отпечатком, однажды принятую в любом продукте вашей студии, панель повторно не спрашивает.
Новая редакция у установленного продукта — окно при обновлении; старая версия у участника работает дальше.

Соглашение — договор между вами и участником; платформа его условия не оценивает. Модератор проверяет только то, что
перечислено в [разделе 6](#6-модерация).

**Кто увидит окно.** User Panel 1.0.2679 и новее. Сервер принятие для установки и покупки **не требует**: старые панели
и прямые вызовы API ставят продукт без окна. Поэтому окно соглашения в самом плагине оставьте — оно сработает там, где
панель не спросила.

## 2. Отпечаток текста («v1»)

Принятие в панели и проверка в плагине сходятся по паре **код + отпечаток**. Отпечаток считает сервер по тексту,
который вы сохранили; присланный вами отпечаток служит только для сверки. Чтобы плагин узнал принятие из панели, он
должен передавать в `GetState` **тот же код и отпечаток, посчитанный тем же способом**. Обычный SHA-256 от байтов
файла этим способом не является.

Способ «v1»:

1. Переводы строк сводятся к `\n`: CRLF, LF и CR дают один отпечаток.
2. Служебная шапка — от первой строки `---` до следующей строки `---` включительно — убирается. Затем убираются
   комментарии `<!-- … -->`, края текста обрезаются.
3. Текст делится на блоки. Строка, начинающаяся (без отступа) с `### `, — блок вида 3, с `## ` — 2, с `# ` — 1,
   с `- ` — 4 (пункт перечня, всегда одна строка). Остальное — абзац, вид 0: его строки обрезаются по краям и
   склеиваются одним пробелом. Абзац кончается пустой строкой, заголовком или пунктом. Текст блока обрезается по краям.
4. Строка для хэша — блоки подряд в виде `<вид>\t<текст>\n`, UTF-8 без BOM. Отпечаток — SHA-256, 64 шестнадцатеричных
   знака в нижнем регистре.

**Не меняют отпечаток:** вид перевода строк, лишние пустые строки, перенос строки внутри абзаца, пробелы в конце
строк, отступы у строк абзаца, содержимое служебной шапки и комментариев. **Меняет** любое видимое изменение: слово,
знак, вид блока, разметка внутри строки (`**жирное**` входит в текст блока как есть). Отступ перед `#` или `- `
меняет вид блока — заголовок или пункт становится абзацем, — а значит, и отпечаток.

Особые случаи — буквальным прочтением правил:

- шапкой считается первая пара строк `---` в любом месте текста, не только в начале;
- пункт или заголовок с отступом (`  - пункт`, `  # Заголовок`) — абзац;
- строка сразу после пункта — новый абзац, а не продолжение пункта;
- `####` и глубже, `#` без пробела — абзац.

**Эталон.** Текст (с любыми переводами строк):

```markdown
---
служебная шапка
---
# Соглашение

## Редакция 1

### 1. Общие

**1.1.** Первый пункт
продолжение абзаца.

- раз
- два
```

даёт отпечаток `639a00685cae107e794f09af876c16c6593af65a2f0803e817d588272c9a9b0a`. Проверьте на нём свою реализацию.

### Реализация на C# (net48 и net8)

В SDK 2.4.0 отдельного публичного метода отпечатка нет — используйте пример ниже; он совпадает с серверной реализацией.

```csharp
using System;
using System.Collections.Generic;
using System.Globalization;
using System.Security.Cryptography;
using System.Text;
using System.Text.RegularExpressions;

public static class AgreementFingerprintV1
{
    public static string Compute(string markdown)
    {
        // 1. Переводы строк — к \n.
        var text = markdown.Replace("\r\n", "\n").Replace('\r', '\n');
        // 2. Шапка, затем комментарии, затем края.
        text = RemoveFrontMatter(text);
        text = Regex.Replace(text, @"<!--[\s\S]*?-->", string.Empty);
        text = text.Trim();

        // 3. Блоки «<вид>\t<текст>\n».
        var source = new StringBuilder();
        var paragraph = new List<string>();
        Action flush = () =>
        {
            if (paragraph.Count == 0) return;
            source.Append("0\t").Append(string.Join(" ", paragraph)).Append('\n');
            paragraph.Clear();
        };

        foreach (var line in text.Split('\n'))
        {
            if (line.Trim().Length == 0) { flush(); continue; }

            int kind; string rest;
            if (line.StartsWith("### ", StringComparison.Ordinal)) { kind = 3; rest = line.Substring(4); }
            else if (line.StartsWith("## ", StringComparison.Ordinal)) { kind = 2; rest = line.Substring(3); }
            else if (line.StartsWith("# ", StringComparison.Ordinal)) { kind = 1; rest = line.Substring(2); }
            else if (line.StartsWith("- ", StringComparison.Ordinal)) { kind = 4; rest = line.Substring(2); }
            else { paragraph.Add(line.Trim()); continue; }

            flush();
            source.Append(kind.ToString(CultureInfo.InvariantCulture)).Append('\t').Append(rest.Trim()).Append('\n');
        }
        flush();

        // 4. SHA-256 от UTF-8 без BOM, 64 hex в нижнем регистре.
        using (var sha = SHA256.Create())
        {
            var hash = sha.ComputeHash(new UTF8Encoding(false).GetBytes(source.ToString()));
            var hex = new StringBuilder(64);
            foreach (var b in hash) hex.Append(b.ToString("x2", CultureInfo.InvariantCulture));
            return hex.ToString();
        }
    }

    private static string RemoveFrontMatter(string text)
    {
        var lines = text.Split('\n');
        var first = -1;
        for (var i = 0; i < lines.Length; i++)
        {
            if (lines[i].Trim() != "---") continue;
            if (first < 0) { first = i; continue; }

            var kept = new List<string>();
            for (var j = 0; j < lines.Length; j++)
                if (j < first || j > i) kept.Add(lines[j]);
            return string.Join("\n", kept);
        }
        return text;
    }
}
```

**Отпечаток без своего кода.** Developer Panel показывает «Отпечаток платформы (v1)» под предпросмотром, API — поле
`textSha256` в ответе. Его можно вшить в плагин константой рядом с текстом. Надёжнее держать текст соглашения одним
файлом: вложить его в сборку, считать отпечаток при запуске реализацией выше и тот же файл вставлять в форму выпуска.

## 3. Developer Panel

Продукт → «Версии» → «Новый релиз» (или правка черновика) → раздел **«Лицензионное соглашение»**:

| Поле | Что указать |
|------|-------------|
| «Показывать соглашение перед установкой» | Галочка. Снята — выпуск без соглашения |
| «Код соглашения» | Тот же код, что плагин передаёт в SDK, например `myproduct-eula` |
| «Название» | Заголовок над текстом в окне; в отпечаток не входит |
| «Текст» | Markdown: `#`, `##`, `###`, `- ` — пункт, `**жирное**` |
| «Продукт отправляет анонимные счётчики команд» | В окне появится галочка согласия на счётчики (раздел 5) |
| «Отпечаток из вашей сборки» | Необязательно. Указан и не совпал с отпечатком платформы — сохранение отклоняется |

Ниже — «Предпросмотр — так увидит участник» и «Отпечаток платформы (v1)»: окно панели рисует ровно те блоки, от
которых взят отпечаток.

Сохранение выпуска сначала сохраняет редакцию и только потом создаёт или правит выпуск: отказ по соглашению выпуск не
меняет. Форма нового релиза подставляет самую новую редакцию, у которой есть выпуск; если такой нет — последнюю
сохранённую. Это правило формы; правило сервера для выпуска, созданного через API без поля `agreementRevisionId`,
другое — см. [раздел 4.2](#42-привязка-к-выпуску).

## 4. API

База и токен — как в [Publishing API](grossgeo-publishing-api-guide.md). Формат ошибок тот же: RFC 7807, машинный код в
поле `code`, пояснение в `detail`.

### 4.1. Редакции соглашения

| Маршрут | Скоуп | Что делает |
|---------|-------|-----------|
| `GET /api/developer/products/{productId}/agreement-revisions` | `products:read` | Редакции продукта, новые первыми |
| `POST /api/developer/products/{productId}/agreement-revisions` | `products:write` | Создать редакцию |

Тело `POST`:

| Поле | Тип | Правило |
|------|-----|---------|
| `agreementCode` | строка | `^[a-z0-9][a-z0-9._-]{0,63}$` — как в SDK, только нижний регистр |
| `title` | строка | Обязательно, до 200 знаков |
| `textMarkdown` | строка | До 100 000 знаков; после правил «v1» должен остаться хотя бы один блок |
| `usesTelemetry` | bool | Продукт отправляет счётчики команд — в окне будет галочка согласия |
| `textSha256` | строка или нет поля | Только сверка: 64 hex; не совпал с отпечатком сервера — отказ |

```bash
curl -sS -X POST "$BASE_URL/api/developer/products/$PRODUCT_ID/agreement-revisions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"agreementCode":"myproduct-eula","title":"Лицензионное соглашение MyProduct",
       "textMarkdown":"# Соглашение\n\n- Пункт первый\n- Пункт второй\n",
       "usesTelemetry":true,
       "textSha256":"<отпечаток из вашей сборки>"}'
```

Ответ `200`:

```json
{
  "id": "3c5e…",
  "productId": "9b1d…",
  "agreementCode": "myproduct-eula",
  "title": "Лицензионное соглашение MyProduct",
  "textMarkdown": "# Соглашение\n\n- Пункт первый\n- Пункт второй\n",
  "textSha256": "<отпечаток, посчитанный сервером>",
  "fingerprintMethod": "v1",
  "usesTelemetry": true,
  "createdAt": "2026-11-11T09:30:00Z",
  "releaseVersions": []
}
```

`releaseVersions` — версии выпусков, к которым редакция привязана (заполняется в списке `GET`).

**Повтор безопасен.** Если код, название, текст и признак счётчиков совпадают с **последней** редакцией продукта,
новая не создаётся — вернётся существующая с тем же `id`. Править или удалять редакцию нельзя: изменённый текст
сохраняется новой редакцией.

| Код | Статус | Значение |
|-----|--------|----------|
| `AGREEMENT_CODE_INVALID` | 400 | код не подходит под форму |
| `AGREEMENT_TITLE_INVALID` | 400 | название пустое или длиннее 200 знаков |
| `AGREEMENT_TEXT_EMPTY` | 400 | видимого текста нет (шапка и комментарии не в счёт) |
| `AGREEMENT_TEXT_TOO_LONG` | 400 | текст длиннее 100 000 знаков |
| `AGREEMENT_FINGERPRINT_MISMATCH` | 400 | присланный `textSha256` не совпал; оба отпечатка — в `detail` |
| `STUDIO_PRODUCT_NOT_FOUND` | 404 | продукта нет у вашей студии |

`AGREEMENT_FINGERPRINT_MISMATCH` означает, что текст в запросе отличается от текста в сборке: плагин не узнает
принятие из панели и покажет своё окно повторно.

### 4.2. Привязка к выпуску

Редакция привязывается полем `agreementRevisionId` в создании черновика
(`POST /api/developer/products/{productId}/releases`) и в правке
(`PUT /api/developer/releases/{releaseId}`, с `If-Match`). Карточка выпуска (`GET /api/developer/releases/{releaseId}`)
возвращает это поле; `null` — соглашения нет.

| Значение `agreementRevisionId` | Создание выпуска | Правка выпуска |
|--------------------------------|------------------|----------------|
| поле не передано или `null` | редакция самого позднего по созданию выпуска продукта, у которого соглашение было (статус выпуска не важен); такого нет — без соглашения | без изменений |
| `"00000000-0000-0000-0000-000000000000"` | без соглашения | снять соглашение |
| `id` редакции этого продукта | эта редакция | эта редакция |
| `id` чужой или несуществующей редакции | `400 AGREEMENT_REVISION_NOT_FOUND` | `400 AGREEMENT_REVISION_NOT_FOUND` |

Правка возможна только у черновика или отклонённого выпуска (иначе `INVALID_STATUS`): у опубликованного выпуска
соглашение не меняется — выпустите новую версию. В пайплайне передавайте поле **явно** — так выпуск не унаследует
редакцию, которую вы не имели в виду.

```bash
curl -sS -X POST "$BASE_URL/api/developer/products/$PRODUCT_ID/releases" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"version":"1.5.0","channel":"Stable","distributionType":"Bundle",
       "targetPlatforms":["AutoCAD"],
       "agreementRevisionId":"3c5e…",
       "changelog":"Новая редакция соглашения"}'
```

### 4.3. Что увидит участник

`GET /api/catalog/products/{productId}/agreement?releaseId={releaseId}` — публичный маршрут, по нему панель получает
текст для окна. Без `releaseId` — соглашение предлагаемого выпуска (Stable, иначе Beta). Отдаёт только опубликованные
выпуски, которые спрашивающему видны в каталоге.

```json
{
  "agreement": {
    "revisionId": "3c5e…",
    "releaseId": "7a20…",
    "productId": "9b1d…",
    "productName": "MyProduct",
    "studioId": "51f0…",
    "studioName": "Моя студия",
    "agreementCode": "myproduct-eula",
    "title": "Лицензионное соглашение MyProduct",
    "textSha256": "<отпечаток>",
    "textMarkdown": "…",
    "usesTelemetry": true
  }
}
```

`{"agreement": null}` — у выпуска соглашения нет; `404` — нет продукта или такого опубликованного выпуска.

## 5. Счётчики команд: галочка в окне

Галочка «Отправлять анонимные счётчики команд» появляется, только если у редакции `usesTelemetry: true`. Она **снята,
пока участник не решал**; иначе показывает его текущее решение по студии. Решение о счётчиках действует для всей студии (все её продукты), как и в SDK. По нажатию «Принимаю»:

| Галочка | Прежнее решение участника по студии | Что записывается |
|---------|-------------------------------------|------------------|
| отмечена | не «да» | «да» |
| отмечена | «да» | ничего |
| снята | «да» | «нет» |
| снята | ещё не решал | «нет» |
| снята | «нет» | ничего |

Плагин видит результат в `GetState(...).Telemetry` и `TelemetryConsent`: «да» — `Granted`, «нет» — `Revoked`.
Если «нет» выводится только из нетронутой галочки, а у участника есть ещё не отправленное решение по счётчикам из
плагина, — «нет» не записывается: более раннее решение человека не перекрывается.

Согласие на счётчики нельзя делать условием лицензии — такой выпуск модератор отклонит.

## 6. Модерация

Выпуск с **новой** редакцией — той, что не стоит ни на одном другом опубликованном выпуске продукта, — после отправки
всегда уходит модератору-человеку, даже у проверенной студии: в ответе отправки `autoApproved: false`, статус
`PendingReview`. Выпуск с уже опубликованной редакцией проходит модерацию по общим правилам.

Модератор видит код, отпечаток, текст и разницу по блокам с редакцией последнего опубликованного выпуска и проверяет
три вещи:

- нет недопустимого содержимого;
- текст не возлагает ответственность на платформу;
- согласие на счётчики не сделано условием лицензии.

Отказ — статус `Rejected`, причина в `rejectionReason`; черновик можно исправить (в том числе привязать другую
редакцию) и отправить снова.

## 7. Сторона плагина

Плагин узнаёт о принятии через `GrossGeo.SDK.Legal` (SDK 2.4.0 и новее):

- `GrossGeoAgreements.For(<ключ продукта>).GetState(<код>, <отпечаток v1>)` → `Acceptance = Accepted`,
  `Source = Account` — участник принял соглашение в панели (или на другой машине своей учётной записи).
- Принятие из панели становится видно не сразу: панели нужно связать ключ продукта на машине со студией. Обычно это
  несколько секунд после первого обращения плагина к SDK, при сбое сети — до нескольких минут, без входа в панель —
  никогда. До этого `GetState` отвечает `NotAccepted`.
- Рекомендация: заводите клиент и подписывайтесь на `Changed` при загрузке плагина, а перед показом своего окна
  подождите несколько секунд события `AcceptanceChanged`.

Подробности и пример — [SDK 2.4: соглашение, принятое в User Panel](grossgeo-sdk-2.4-guide.md#соглашение-принятое-в-user-panel).

## 8. Ограничения первой версии

- **Только текст Markdown.** Ссылки на внешний документ вместо текста нет; перевода нет — один текст на редакцию.
- **Внешняя лицензия.** У продукта в режиме «Внешняя лицензия» окно показывается перед установкой и обновлением MSI
  в панели. Покупка такого продукта идёт на вашем сайте, вне панели, поэтому при покупке окна нет.
- **Без окна:** User Panel старше 1.0.2679 и прямые вызовы API; держатели лицензий продукта, снятого с витрины (маршрут
  раздела 4.3 им отвечает `404`, установка идёт дальше). В этих случаях сработает окно в плагине.
- **Отпечаток — только «v1».** В SDK 2.4.0 отдельного публичного метода отпечатка нет — используйте пример из раздела 2.
